# implement

Kit root (`<KIT>` in shared files and agents): `${CLAUDE_SKILL_DIR}/../core`. Include `Kit root: ${CLAUDE_SKILL_DIR}/../core` in the prompt of every agent you spawn. Work from the project root (`${CLAUDE_PROJECT_DIR}`) and do not `cd` away from it.

Input: $ARGUMENTS
State: !`python3 -I "${CLAUDE_SKILL_DIR}/../core/scripts/dev_state.py" --root "${CLAUDE_PROJECT_DIR}" status --short --quiet-if-missing`
Git: !`git status --short 2>/dev/null | head -20`

Let `DS` = `python3 -I "${CLAUDE_SKILL_DIR}/../core/scripts/dev_state.py" --root "${CLAUDE_PROJECT_DIR}"`.

## Setup (once per run)
1. Read `${CLAUDE_SKILL_DIR}/../core/shared/conventions.md` (§5 commits, §6 autonomy), `${CLAUDE_SKILL_DIR}/../core/shared/checklists/test-pyramid.md`, `.dev/architecture.md`, `.dev/decisions.md`; keep `.dev/design/*.md` and `.dev/prd.md` at hand for the tasks touched. Load the autonomy policy from `DS status --json`.
2. Reconcile: run `DS reconcile` first (it closes the slots a stopped session left open and blocks the tasks it left `in_progress` with their attempt in the ledger, `conventions.md` §17). If the working tree has uncommitted changes that belong to a task (every task is delegated to an `implementer`, step 2 of the loop), never continue it in the main checkout: `DS reconcile --adopt T-xxx` moves its files into the task's worktree, and the task goes on there. **Work an earlier attempt left** (a `Previous attempt` with a branch in the brief, a worktree on `dev-kit/T-xxx` anywhere, an answer that says to adopt it): `DS start T-xxx --resume` takes it over and records the start, then the task goes on as usual: `slot open --worktree` reuses its worktree for the implementer. Never apply a worktree's work by hand (`git apply`, `git checkout <branch> -- …`, copying files): the task would run without a start and the board would show nothing running (`conventions.md` §17). If they belong to nothing known, apply `pause_policy.dirty_tree` (`conventions.md` §10): `ask` → stop and ask what to do; `auto_recommend` → `git stash push -u -m "dev-kit auto <date>" -- . ':(exclude).dev'` and log it (never stash `.dev/`, `conventions.md` §5). Never commit unknown changes.
3. Parse arguments: a specific task id; `--tasks N` (default: until the current milestone's tasks are all done); `--milestone Mn`; `--parallel N` (use `implementer` agents for independent ready tasks, max N; `--parallel auto` = the number set on the board's Autopilot card); `--skip-gate` (writes an ADR `(user)` and runs `DS gate <prev> skipped`).

## Loop per task
Hotfix tasks (`lane: hotfix`, `conventions.md` §15) come first from `DS next`, even with a pending gate; only one is open at a time. When a hotfix is done, the next step is `qa --scope <task>`, then `release --hotfix` (which deploys it when there is production). Cool-down tasks (`lane: cooldown`) come next. End the run report with one tip from `DS tip implement`.
Log `skill_start`/`skill_end` once per run (`conventions.md` §13); the task transitions are logged by `dev_state.py` itself.
1. `DS next [--milestone Mn] --json` → if exit code 3, read the reason: milestone complete → stop and say "run `qa <M>`" (continue into `qa` when invoked by `autopilot`); gate pending → stop unless `--skip-gate`; only blocked tasks → report them and stop.
2. `DS start T-xxx` (it records the task's tier and route and prints them: `· opus / high (quality)`). **Every task is delegated to one `implementer` subagent in its own worktree, whatever its tier** (`speed`, `balanced`, `balanced+` or `quality`), exactly as in `--parallel` with N = 1: never implement a task yourself in this session, so the task runs on its route's model and effort (not on this session's), shows in Claude Code's task list (`/tasks`) and stays inside its fence. `DS slot open N --task T-xxx --worktree`, then `DS brief T-xxx` (after the slot, so it carries the `Worktree:` line): it prints the task with its languages, commands, verification rule, any `Previous attempt` from the ledger (the implementer continues from it), the `Tier:`/`Route:` lines (`conventions.md` §9 "Tier per task" and "Router") and the `Implementer:` line. Spawn the implementer as in `--parallel` below, with `run_in_background: true` and the `model` and `effort` of the `Implementer:` line: it is the route, and it wins over the tier's arm when they differ (the router moved it, and the line says why); never pick one yourself. Applying the route is not an escalation and needs no consent. While it works, read the task's acceptance, test_notes and files and the spec sections they touch, so you can review its diff.
3. When the report arrives, integrate it as in `--parallel` below ("When a report arrives"): `DS slot close N`, `DS slot apply N`, then run lint, type-check and the task's affected tests yourself (the brief's verification rule: its ACs' tests and the tests of the modules it changed) and fix regressions (in the worktree through the implementer, or in the main checkout for a small fix). The **full** suite runs per `autonomy.verify` (step 6b), not necessarily after every task. For a `balanced+` or `quality` task, cross-check every file of the task and every AC against the report and the diff before the commit.
3a. Accumulating files and shared resources: check that the task wrote its CHANGELOG entry to `changelog.d/T-xxx.md` (setup notes to `docs/setup.d/T-xxx.md`) instead of editing `CHANGELOG.md` or `README.md`, and used the message catalog of `ux-flows.md` §7.1 for validation and status texts; take `DS lock acquire <resource> --holder <you>` before using a resource listed as exclusive in `architecture.md` §7 and `DS lock release` after.
3b. Task checks (before the commit; the gate then confirms instead of discovering): read the implementer's `self_check` (`agents/implementer.md` step 4b: AC ↔ test, copy, static a11y on what it touched). Then, per `autonomy.task_checks` (default `ui`): when the task touches UI files (components, templates, styles, string catalogs; with `all`, any task with user-facing strings), spawn `copy-reviewer` (`model: sonnet`) and `a11y-auditor` (`model: haiku`) with `Mode: static`, scope `T-xxx`, `effort: medium`, `Output file: .dev/qa/T-xxx/precheck/<agent>.json`, in parallel and in the background. Fix their critical/high findings inside the task and re-run the task's tests; medium and low go into the commit body as known. Then record what they reviewed in the ledger, so the gate does not review the same unchanged files again (`conventions.md` §18): for each agent, `DS ledger record --prefix audit:<copy|a11y> --files <the task's UI files it reviewed> --context <its context, the same files qa §3 passes for that dimension: the checklist (`copy-review.md` or `wcag-2.2-aa.md` in `${CLAUDE_SKILL_DIR}/../core/shared/checklists/`), `.dev/design/ui-spec.md`, `.dev/design/ux-flows.md`> --salt tier:<model> --findings-from .dev/qa/T-xxx/precheck/<agent>.json` after the fixes (a file with a finding left is recorded as such and the gate reviews it again; the dynamic a11y checks of the QA harness are not covered by this). `off` skips the agents, not the self-check.
4. Decisions (the report's `decisions_taken` and `needs_decision`): apply the autonomy rule. `decide_alone` → decide, append `ADR-nnn (auto)` to `.dev/decisions.md`, optionally `DS add-question`. `always_ask` → first apply the category's `pause_policy` action (`conventions.md` §10: `preauthorize` within its limit, `auto_recommend`, or `park`); only for `ask`: if running under `autopilot` and the task can be finished without the answer, finish it with the safest assumption and queue the question; otherwise `DS block T-xxx --reason "needs decision: ..."` and ask the user with AskUserQuestion (recommended option first), then `DS unblock` and continue.
5. Time budget: if the task is not converging after roughly `task_time_budget_min` of effort (many failed attempts, environment problems), keep the partial work on the implementer's worktree branch `dev-kit/T-xxx`, record it with `DS ledger put task:T-xxx --result failed --note "<what was tried, what failed>" --ref <branch>`, then `DS block T-xxx --reason "<concrete blocker>"`, write what you tried in `.dev/log.md` via the block reason, and move to the next ready task.
6. Commit (when `commit_per_task` is true; if a hook rejects it, fix and retry, and only then take the SHA): `git add` only the task's files (and lockfiles/config it legitimately changed) plus the tracked `.dev/` files (state, plan, decisions, log of the previous step); subject from `autonomy.commit_style` (default `[T-xxx] <type>: <summary>`; trailer `Refs: T-xxx` when the template has no `{task}`, `conventions.md` §5): `git commit -m "<subject>" -m "<body: what, ACs, how verified>"`. Then `DS done T-xxx --commit $(git rev-parse HEAD)` and `DS slot close N --remove`. If committing is disabled, just `DS done T-xxx` (and run the full suite after every task: without commits there is nothing to bisect).
6b. Full suite (`autonomy.verify.full_suite`, default `per_batch`; `conventions.md` §18): `DS verify due` (add `--boundary` at the end of a `--parallel` batch and before you stop for any reason) exits 0 when it is due: `per_task` after every task; `per_batch` every `batch_size` tasks (default 4), at the end of each parallel batch and of the run; `per_milestone` only when the milestone's tasks are done (all modes run it then, so `qa` finds a green run to reuse). When due, run the full suite on HEAD as a job (`DS job start full-suite --cmd "<test command>"`, then `DS job wait full-suite` until it exits 0 or 1; never check it with `ps`/`pgrep`; exit 4 = timed out or lost: a Needs-you item, record nothing and stop the batch; `conventions.md` §17). Green → `DS tests record --kind all --passed <n> --failed 0 --command "<test command>" --duration <s>` (add `--coverage <pct>` when measured), so the test auditor and the gate reuse it. Red → `DS verify bisect --test "<command that runs only the failing tests>" [--setup "<link node_modules/.venv>"] --json` finds the first commit since the last green full run that fails them, in a scratch worktree (your checkout is untouched), and names its task. Create one fix task for it (`DS add-task --type fix --milestone <its milestone> --title "Fix <failing tests> broken by T-xxx" --files <its files> --source "verify:<sha>"`) and implement it **next**, before any other task, with the failing output and the bisect result in its brief; then run the full suite again. `passes_on_head` means the failure did not reproduce in a clean tree: a flaky test or local state, which is a `test-auditor` matter; record nothing and re-run once. Never start a new batch on a red full suite.
7. One-line progress note to the user (task, tests count, commit short SHA). Repeat.

## `--parallel N`
N is the number given, or with `--parallel auto` 3 (1 to 6; 1 = one task at a time, as without `--parallel`). Before **every** batch, run `DS next --batch <N or auto> --json` again (its `batch_size` says the N it used); implementers already running finish their task. Pick the batch with `DS next --batch N --json`: up to N ready tasks with no file in common and at most one that touches a serialising file (manifests, lockfiles, migrations, registries, barrels, CHANGELOG/README, or `shared` in the plan). If the batch has fewer than N tasks and the JSON has `maybe_false_deps`, review each listed dependency before waiting: if it is false, edit the task's `deps` in `plan.md`, record a one-line ADR, run `DS sync-plan` and start the task; if it is real, leave it and never force-start the task. Never ignore a listed dependency silently. **Serialize** (never run two at once) tasks that touch shared files: route/registry indexes, package `__init__`/barrel files, the migrations head (any task that adds a migration), lockfiles and manifests, shared config.
- Spawn one `implementer` per task with the Agent tool, `run_in_background: true`, the `model` and `effort` of its route (the brief's `Implementer:` line, or `DS tier T-xxx --json` → `final_model`, `final_effort`; `conventions.md` §9; pass them explicitly) and **no `isolation`**: the kit creates each worktree itself, from the work branch (Claude Code's own worktree isolation picks its base and can start from the wrong branch); set the Agent `description` to `T-xxx <short title>` and give each the output of `DS brief T-xxx` as the base of its prompt (task, the `Scope: T-xxx` line the board links by, languages, commands, the verification rule: unit, lint, type-check and only the integration tests it affects), the task id, the language, `Project root: ${CLAUDE_PROJECT_DIR}` (it runs `dev_state.py --root` on it from its worktree), a distinct `Slot: N` and the isolation line (`resource-isolation.md`: own port, database, scratch folder and PIDs). Before spawning, open its fence and worktree: `DS slot open N --task T-xxx --worktree` (it creates `.dev/run/worktrees/T-xxx` on `dev-kit/T-xxx` from the work branch, refuses a base without the project's `.dev/state.json`, and prints the worktree and its base; the hook then denies edits outside the task's files and outside the worktree, and the git commands of `conventions.md` §17). Run `DS brief T-xxx` after it, so the brief carries the `Worktree:` line. `DS start` each with `--force`. The plugin hooks log each agent (`conventions.md` §13).
- **Work ahead** (`conventions.md` §19): when `DS next --batch N --json` carries `branch` (`dev-kit/R<n>` while an earlier release waits for approval, or `dev-kit/M<n>` while the milestone before is in QA), every task of the batch belongs on that branch, never on the main branch: create its worktree once with `DS pipeline worktree <branch>`; `slot open --worktree` then starts the implementers' worktrees from that branch and `slot apply` integrates into that worktree instead of the main checkout, where you commit (same steps as below). `DS start` records the branch. A task that a fix of the milestone in QA sent back (`redo_after`) waits for that gate.
- When a report arrives, integrate **one at a time** in the main checkout: first `DS slot close N` (the agent is done), then `DS slot apply N`: it checks the agent's changes against the fence from the worktree's base (exit 1 with the files = the agent changed a file outside its task, for instance through Bash: revert those files in the worktree or re-plan the task's files, never merge them silently) and applies them, staged, to the main checkout (exit 1 on a conflict: it logs `merge_conflict`; re-run that task alone after the others, its worktree is kept), run lint, type-check and the task's affected tests yourself (step 3), review the diff briefly, record the report's facts (`DS fact add --text "<text>" --evidence "<evidence>" --files <files> --acs <acs> --origin T-xxx` each; `DS fact stale K-nnn --by T-xxx --evidence "<evidence>"` for each in `facts_contradicted`; a refused one is dropped, never rewritten to pass), commit (hooks run only here, sequentially) and `DS done`; the full suite runs after the batch (step 6b, `--boundary`). If a hook rejects the commit, fix and commit again, then record the SHA of the commit that landed (`git rev-parse HEAD` after it succeeds). Then `DS slot close N --remove` deletes the worktree and its branch.
- `needs_decision` → handle per step 4; `blocked` → `DS block` (the router counts it: two failures in a row in one context raise it one tier for the rest of the milestone, and `DS block` says so). A `spec_deviation` in the report → update the spec file or create a fix task, never leave spec and code silently apart.
- After each batch run `DS cleanup`. Keep the main context for coordination only.
- Fix tasks from a gate (`type: fix`) are one round: implement all of them, then hand over to `qa` once. Never deploy, start a preview or re-run auditors between fix tasks (`conventions.md` §12).

## Stop conditions and report
Before `skill_end`, run `python3 -I "${CLAUDE_SKILL_DIR}/../core/scripts/dev_cost.py" --root "${CLAUDE_PROJECT_DIR}" ingest` (token usage per stage, `conventions.md` §14).
Stop when: requested tasks done; milestone complete (announce the gate); an `always_ask` question with action `ask` cannot be deferred; three consecutive tasks blocked (environment problem; `pause_policy.blocked_env`). Always end with: tasks completed (ids + SHAs), tasks blocked (reasons), decisions taken (ADR ids), open questions added, and the next command.

## Never
- Never skip or weaken tests to pass; never commit with failing lint, type-check or affected tests, and never start new tasks on a red full suite; never edit `state.json` manually; never push unless `may_push` is true and the brief asked for it.

**Last line** (`conventions.md` §15): end the final report with the next command alone on the last line, written in full: `/dev-kit:qa M1` when the milestone is complete, otherwise `/dev-kit:implement`. Claude Code then offers it as the greyed-out prompt suggestion (Tab or Right arrow).

## Existing projects (brownfield)

When state has `brownfield` (`conventions.md` §16): follow the folder layout, test framework, test location and naming, and the build/test/lint commands in `.dev/discovery.md` §3–4 (they override `test-pyramid.md` defaults and `architecture.md` §8 where they differ); never add a runner, linter, formatter or build tool without an `always_ask` decision. Uncommitted changes that belong to no task are the user's work: always ask (never stash them on your own). In `maintenance` mode the tasks come from `issue` in the open maintenance milestone (`M<n> — Maintenance`, numbered from `brownfield.first_milestone`); when its tasks are done, the milestone goes to `qa M<n>` like any other, and new issues then open `M<n+1> — Maintenance`. With no task at all, suggest `/dev-kit:issue`.

## Round child (`--round-child`)
Started by `DS round run` in a headless session of its own (`conventions.md` §17), with the same project and permission mode. Run exactly the milestone given (`--milestone` implied by the scope), with `--parallel auto` when the brief allows parallel work, then stop. Never log `session_start` (the events go to the parent's session by themselves). Nobody is at the console: every question that would ask the user is parked (`DS add-question … --skill implement` with the recommended answer first, `conventions.md` §10), and a permission Claude Code denies is not retried; when one is needed to go on, park as `pause_policy` says and stop. Every task you work on is started first (`DS start`, or `DS start T-xxx --resume` for an earlier attempt's work), even when a question's answer told you to adopt existing work. When a denied permission stops the work, end at once with one line and do not run `DS block` yourself; `round run` reconciles the state after you. End with one line (ids, counts, scores); the parent reads `round run`'s JSON summary, not your reply or the reports.
