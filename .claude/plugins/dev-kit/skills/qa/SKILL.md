Use when a milestone's tasks are done, before the next milestone, or with --only to run a subset.

# qa

Kit root (`<KIT>` in shared files and agents): `${CLAUDE_SKILL_DIR}/../core`. Include `Kit root: ${CLAUDE_SKILL_DIR}/../core` in the prompt of every agent you spawn. Work from the project root (`${CLAUDE_PROJECT_DIR}`) and do not `cd` away from it.

Input: $ARGUMENTS
State: !`python3 -I "${CLAUDE_SKILL_DIR}/../core/scripts/dev_state.py" --root "${CLAUDE_PROJECT_DIR}" status --short --quiet-if-missing`

Let `DS` = `python3 -I "${CLAUDE_SKILL_DIR}/../core/scripts/dev_state.py" --root "${CLAUDE_PROJECT_DIR}"` and `SC` = `python3 -I "${CLAUDE_SKILL_DIR}/../core/scripts/dev_score.py"`.

## 1. Prepare
1. Read `${CLAUDE_SKILL_DIR}/../core/shared/conventions.md` (§7 severities and scoring) and the template `${CLAUDE_SKILL_DIR}/../core/shared/templates/qa-report.md`. Determine the milestone (argument, or the latest one whose tasks are all done and gate is pending). Run `python3 -I "${CLAUDE_SKILL_DIR}/../core/scripts/dev_detect_stack.py" "${CLAUDE_PROJECT_DIR}" --tools` once on UI milestones and tell the visual and a11y auditors what it found (harness scripts, Playwright, Chromium, axe); when `visual_ready` is false and the plan has no QA harness task, say in the report that visual and a11y ran from static reading and suggest the harness (`${CLAUDE_SKILL_DIR}/../core/shared/templates/qa-harness.md`). Ensure the working tree is clean outside `.dev/` (`git status --short -- . ':(exclude).dev'`); otherwise apply `pause_policy.dirty_tree` (`conventions.md` §10): `ask` → ask to commit or stash; `auto_recommend` → stash with a dated message, never `.dev/` (`git stash push -u -m "dev-kit auto <date>" -- . ':(exclude).dev'`), and say so in the report. `--scope T-xxx` (a hotfix or a single task) audits only that task's commit (`git show <sha>` from `DS status --json`) and never touches the milestone gate: see §4.
2. Existing project (state has `brownfield`): scope every auditor to what changed since `brownfield.baseline_ref` (`git diff <baseline_ref>..HEAD`); failures already listed in `.dev/qa/baseline.md` are not F-001, and problems found only in untouched legacy code are marked `"legacy": true` by the auditors (tell them so in the prompt; `conventions.md` §16), never blocking findings or fix tasks. Then get the suite result once for everyone: `DS tests lookup --kind all --json` (exit 0: a green run recorded on this code, by `implement` or an earlier round; reuse it) or, on exit 3, run the test suite yourself once (command in `architecture.md` §8) and record it with `DS tests record --kind all --passed <n> --failed <n> --command "…" --duration <s>`. The test auditor reads the same record instead of running the suite again. A failing suite is finding F-001 (`critical`, auditor `test-auditor`) and the gate cannot pass; still run the agents so fixes are batched.
3. Decide which auditors apply, from the milestone's tasks (`DS status --json`: files, acceptance) and the changed files (`git diff --name-only <before-first-task-commit>..HEAD`):

| auditor | runs when |
|---|---|
| `code-reviewer`, `security-auditor`, `test-auditor`, `spec-tracer` | always |
| `ops-reviewer` | always (light on the first milestone of a new project: config, CI, run-from-clean-checkout) |
| `data-reviewer` | project has a database and the milestone touches schema, migrations, models or queries (or the first milestone of a new project; existing projects: only when the diff touches them) |
| `deps-auditor` | manifests or lockfiles changed in the milestone (or the first milestone of a new project; existing projects: only when the diff touches them) |
| `performance-auditor` | milestone adds or changes endpoints, pages, queries or jobs, or the brief has performance targets |
| `a11y-auditor`, `visual-reviewer`, `copy-reviewer` | milestone touches UI files (components, templates, styles, catalogs) and the product has a UI |

`--only` overrides the selection (aliases: deps, ops, perf). A skipped auditor does not count in the score; say which were skipped and why in the report.

## 2. Run the auditors (parallel, within the host's budget)
Log `DS event skill_start --set skill=qa --set args_kind=milestone` at the start and `skill_end` (with `status`, `duration_s` and your `feedback` on the kit) at the end (`conventions.md` §13).

**Shared baseline (once per round, before any auditor):** write `.dev/qa/<M>/baseline.json` with the suite result of §1.2 (reused or recorded), lint and type-check (their `ledger check`/`put` under `lint:<sha>` and `typecheck:<sha>`, or run once), the data smoke of `architecture.md` §8 when there is one (new tables have rows, jobs report ok; a failure is an `ops` finding `high` in `.dev/qa/<M>/raw/data-smoke.json`, and the environment auditors below do not run this round), and, on UI milestones, one run of the QA harness (`qa:shots`, `qa:a11y`, `shared/templates/qa-harness.md`) into `.dev/qa/<M>/shots/` for the screens `DS ledger plan --prefix shot --files "S-01=<route files>,S-02=…"` says to capture (route files from the screen map in `ui-spec.md`; without a map, every screen; all of them in round 1), recorded afterwards with `DS ledger record --prefix shot` and the visual and a11y raw files as `--findings-from`. Give every auditor `Baseline: .dev/qa/<M>/baseline.json`: no auditor runs the suite, lint, type-check or a browser capture that the baseline already holds (`auditor-output-contract.md`).

**Which files each auditor reviews (incremental, `conventions.md` §18):** for each selected auditor, list the scope's files and run `DS ledger plan --prefix audit:<dimension> --files-from <list> --context <the dimension's context files, §18 table> --salt tier:<model> --shared <shared files of the plan> --seed <M>-r<n> --json` (release, or `incremental.full_on_last_gate` on the last milestone: add `--no-cache`). Round 1 reviews everything (`never`); later rounds review the changed files, the files with findings and the spot sample. Give the auditor `Files to review:` with that list (plus its open findings) and `Reused (verified unchanged):` with the count only.

Give every auditor a distinct `Slot: N` (1, 2, 3…) and the line `Isolation: follow <KIT>/shared/prompts/resource-isolation.md`. **Order by cost:** the static auditors (code, security, spec, copy, deps, ops) start at once; the environment auditors (test, performance, visual, a11y, data) start after the baseline is written and after any long job listed in `architecture.md` §7 (backfill, import, pipeline) has finished, and their prompt says whether a write load is running. **Concurrency:** read `nproc`; the heavy auditors (`test-auditor`, `a11y-auditor`, `visual-reviewer`, `performance-auditor`, and any that starts browsers or e2e) run at most `max(1, nproc // 3)` at a time; the light ones (code, security, spec, data, deps, ops, copy) all at once. Log `agent_spawn` / `agent_end` for each (`conventions.md` §13).

Spawn the selected auditors with the Agent tool, `run_in_background: true`, then wait for all. Always pass `model` and `effort` in the Agent call (`conventions.md` §9: on the first run the agent's tier row 1; the host may ignore the frontmatter). Give each `Output file: .dev/qa/<M>/raw/<agent-name>.json` (several audits of one type: `<agent-name>-<k>.json`; create the folder first). On a re-run, choose the auditors with `SC select --previous .dev/qa/<M>/findings-round-<n-1>.json --since <commit audited in round n-1> --auditors <round-1 auditors> --json`: `rerun` ones are spawned; `carry` ones are not (no open finding and nothing in their dimension changed): copy their previous raw file with `"carried": true` added. A dimension that failed is re-run with the model and effort of the next ladder row (`conventions.md` §9), after the consent that `autonomy.model_policy.mode` requires (read it from `DS status --json`). Give each: the scope (`M1` or `--scope`), the language for prose, `Project root: ${CLAUDE_PROJECT_DIR}`, the base URL if the app is already running, and in existing projects `Baseline: <brownfield.baseline_ref>` with the instruction to audit only `git diff <baseline_ref>..HEAD` and to mark problems that exist only in untouched code `"legacy": true`. Tell visual/a11y/performance auditors whether `autonomy.may_run_servers` is true. Do not pre-load them with opinions. **Round ≥ 2 (delta mode):** also give each re-run auditor the previous findings of its dimension from `.dev/qa/<M>/findings-round-<n-1>.json` (id, severity, title, file, line) and ask it to report each as `closed` or `open` in `previous` (`auditor-output-contract.md`). **Freeze while auditing:** give every auditor `Audited commit: <git rev-parse HEAD>`, and change nothing in the working tree (no fixes, no commits, no formatting) until all of them have returned: a fix made while an auditor is still reading is reported open and costs a round. Fixes start in §4, all of them before the next round. After all auditors return, run `DS cleanup`, then record what each reviewed: `DS ledger record --prefix audit:<dimension> --files-from <its Files to review> --context … --salt … --findings-from .dev/qa/<M>/raw/<agent>.json` (files with a finding are recorded as `findings`, the rest as `ok`). If a spot-checked file got a new finding, run `DS ledger drop --prefix audit:<dimension>:` and re-run that auditor on all its files in this round (`conventions.md` §18 rule 4).

## 3. Score
1. Each agent wrote its result to its `Output file:`. Run `SC check --fix .dev/qa/<M>/raw/*.json`; for a file that is missing or still invalid, send the agent the `check` output once (SendMessage, or re-run it) and check again; if it still fails, record `{"auditor": "<name>", "findings": [{"id":"F-000","severity":"high","title":"auditor produced no parsable result",...}]}` so the gate cannot pass silently. An agent that answered with the JSON in its message instead (no file) gets it written verbatim to the file by you; never reconstruct it from the prose. Do not read the raw files into the conversation: `SC score` and the consolidated findings are enough (`conventions.md` §17).
2. Run `SC score --scope <M> --kind gate --root . --round <n> --out .dev/qa/<M>/scores.json .dev/qa/<M>/raw/*.json`, adding `--previous .dev/qa/<M>/findings-round-<n-1>.json` from round 2 on (`conventions.md` §7 delta mode). Exit 0 = pass, 1 = fail. The command prints the per-dimension table; use it verbatim in the report.
3. Consolidate findings: `SC consolidate --scope <M> --round <n> --out-dir .dev/qa/<M> --root . [--previous .dev/qa/<M>/findings-round-<n-1>.json] .dev/qa/<M>/raw/*.json` writes `findings.json` and `findings-round-<n>.json`: previous findings still open keep their ids (the next round marks them by id), new ones get the next free ids, deferred findings and legacy ones are listed apart, and the same file and line reported by two dimensions are linked with `same_as` (one fix task). Never write these files by hand. Do not change severities to move the score; if a severity is clearly wrong, re-run that auditor with a note instead.
4. **Local deploy** (only if `autonomy.local_deploy.mode` is not `off` and the score verdict is pass; once per round, never per fix task): follow `conventions.md` §11 on the milestone's last commit. On failure add the `ops` finding to `.dev/qa/<M>/raw/local-deploy.json` (`auditor: ops-reviewer`), re-score, and the gate fails.
5. Write `.dev/qa/<M>/report.md` from the template in the user's language: score table, trend versus the previous run (delta: closed · still open · new · deferred lows), blocking findings, deferred findings, decisions, and the local deploy result (URL or path, mode).

## 4. Triage and gate
- Legacy findings (existing projects): for each entry in `scores.json` → `legacy`, `DS add-issue --type <bug, or improvement for docs, licence and style debt> --class <intangible; standard for a critical/high security finding such as a secret in the history> --title "<title>" --severity <severity> --origin qa --note "legacy: qa/<M>/report.md"` unless an open issue already covers it (`DS backlog --json` lists `origin` and `note`); list them in the report under "Pre-existing (not scored)", and tell the user plainly about any critical security one (a leaked secret must be rotated whatever the gate says).
- Blocking findings (`critical`/`high`) → `DS fix-tasks --from .dev/qa/<M>/findings.json --milestone <M>`: one fix task per finding, with its file, AC and `F-00n resolved: <recommendation>` as acceptance, source `qa/<M>/report.md#F-00n`; it skips findings that already have a task, so re-running it is safe. Add the chosen mediums of the next rule with `--include F-00n,F-00m`.
- Dimension below its minimum without blocking findings (many mediums): create fix tasks for the cheapest, highest-penalty mediums first until the projected score clears the cut-off (each medium costs 8 points, low 2); remaining mediums/lows are listed as deferred.
- Gate: if the score verdict is pass → `DS gate <M> passed --score <overall> --count-run`; when it was the last milestone, `DS set phase usability` (or `docs` for products without a UI). Otherwise `DS gate <M> pending --score <overall> --count-run --note "<reasons> → fix tasks T-…"`. The next round is one batch: `implement` runs every fix task, then `qa <M>` runs once (one local deploy, at most); production gets the milestone only after the gate passes (`conventions.md` §12).
- `--scope T-xxx`: no gate. Score with `--scope T-xxx --kind gate` into `.dev/qa/T-xxx/`, then record `DS review hotfix-T-xxx pass|fail --score <overall> --count-run` (a hotfix) or `DS review task-T-xxx …` (any other task); fix tasks go to the task's milestone. `release --hotfix` checks this review.
- Rounds: if `qa_runs` exceeds `autonomy.max_fix_rounds_per_gate`, apply `pause_policy.rounds_exhausted` (`conventions.md` §10; `auto_recommend` accepts with `--force --note "policy:rounds_exhausted"` only where §9 recommends it). With `ask`, stop and ask the user (recommended option first per `conventions.md` §9): keep fixing, accept with `DS gate <M> passed --score <n> --force` plus an ADR (`source: user`), or replan.

## 5. Report to the user
If there are deferred findings, say how many and offer to promote the relevant ones with `/dev-kit:issue --from <F-id> <M>`; end with one tip from `DS tip qa_deferred` (when the gate passed, `DS gate` already printed one: relay it instead of asking for another).
Before `skill_end`, run `python3 -I "${CLAUDE_SKILL_DIR}/../core/scripts/dev_cost.py" --root "${CLAUDE_PROJECT_DIR}" ingest` (token usage per stage, `conventions.md` §14).
Verdict, overall score vs cut-off, the dimension table (one line each), the local preview (URL/command and how to stop it) when there is one, fix tasks created, auditors skipped, and the next command (`implement` for fixes then `qa <M>` again; or next milestone).

## Rules
- Agents are read-only; every state change happens here. Never pass a gate by hand or with failing tests.
- Fix tasks must be concrete (file, condition to verify) so `implement` can execute them without re-reading the report.
- A re-run uses fresh auditor instances that receive the previous findings only to verify them (delta mode), never the previous verdicts; escalating model or effort is allowed only as `conventions.md` §9 says, and never silently.
